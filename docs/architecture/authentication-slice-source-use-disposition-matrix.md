This document defines source-use permission for the authentication proof-substrate slice. It does not create implementation files, implementation directories, schemas, evidence, proof output, generated reports, or runtime code.

## Governance Rules

- The baseline source disposition in the import manifest is not implementation permission.
- Source-use permission is explicit in this document and applies only to the rows in the matrix below.
- No row authorises direct source-path mirroring into USF.
- No row authorises direct copy of runtime/application code.
- Evidence-only rows MUST NOT be imported as runtime code.
- Generated reports remain lowest authority and MUST NOT define implementation behaviour, proof readiness, or semantic authority.
- Historical proof scripts are lineage for proof-command semantics; they are not fresh proof execution.
- Historical data migrations are lineage only; this document does not activate schemas or authorise migration execution.
- Provider mode and environment claims remain separate; hermetic or production-shaped evidence MUST NOT be upgraded to live external-provider or production-live claims.
- Future implementation PRs MUST reconcile every created file to either a source row in this matrix or a new-with-rationale entry in the future USF-61/USF-39 directive.

## Source-Use Policies

| Policy | Permission | Runtime import allowed | Required future treatment |
|---|---|---|---|
| adapt | May use observed behaviour as evidence while changing structure, naming, boundaries, and code to satisfy USF semantic instances. | no direct import | Future target file must cite the semantic instances and source rows it adapts. |
| rewrite | Must be re-authored from USF semantic intent and source lineage. | no direct import | Future target file must cite this matrix and explain why direct adaptation is not permitted. |
| evidence-only | May be cited as historical, behavioural, proof, configuration, generated, data, or semantic evidence. | no | Future implementation cannot derive runtime code from the row; non-runtime use requires explicit new-with-rationale treatment. |
| copy | Not authorised for this slice. | no | A later explicit directive would be required before any row could use this policy. |
| retire | Not used as a source-use permission in this slice. | no | Retire remains a baseline source disposition only unless later promoted into a target-file treatment decision. |
| defer | Not used as a source-use permission in this slice. | no | Deferred work must stay outside the implementation slice. |
| reject | Not used as a source-use permission in this slice. | no | Rejected source cannot be used without a later recorded decision. |

## Target File Treatment

This document intentionally proposes no implementation target files. That preserves the USF-39 gate. Future target files must be introduced only by an explicit implementation directive and must use one of these treatments:

- source-derived-adapt: target file adapts behaviour from one or more rows whose source-use policy is adapt.
- source-derived-rewrite: target file rewrites semantic intent from one or more rows whose source-use policy is rewrite.
- new-with-rationale: target file has no direct source row and must explain the USF semantic reason, authority references, and why no source row applies.
- evidence-only-support: target file is non-runtime validation, proof, test, or documentation support and must not import runtime code from evidence-only rows.

A future implementation PR is incomplete if any target file lacks one of those treatments or if any evidence-only row is used as runtime code.
